# FPGA Simulation Backend Abstraction

Swap the FPGA simulation engine via command-line argument without changing any machine code. Detect backend by file extension: `.json` → built-in gate-level, `.so` → CXXRTL/Verilator, `.vvp` → Icarus.

## Current Architecture

```
Machine (gameboy_v2.c / fpga_test.c)
    │
    │  Uses: ice40up5k_set_pin(), ice40up5k_tick(), ice40up5k_find_pin()
    │  Receives: gpio_line callbacks on output pin changes
    │
    ▼
ice40up5k.c  (device wrapper)
    │
    │  Manages: pin table, name lookup, change detection, callbacks
    │  Delegates: actual simulation to netlist/eval
    │
    ▼
netlist.c + eval.c  (gate-level simulator)
    │
    │  Loads Yosys JSON, topo-sorts cells, evaluates LUT4/DFF/CARRY/SPRAM/BRAM
    │
    ▼
sim_state (flat arrays of nets, cells, hard_cells)
```

The machine-to-FPGA interface is narrow (4 functions + callbacks):

1. `ice40up5k_init(dev, path)` — load design, discover pins
2. `ice40up5k_set_pin(dev, idx, level)` — drive an input pin
3. `ice40up5k_tick(dev)` / `ice40up5k_tick_n(dev, n)` — advance one clock cycle
4. `ice40up5k_find_pin(dev, name)` — resolve pin name → index
5. Output: each pin has a `struct gpio_line out` callback that fires on level change

## How the built-in sim works

### Initialization

`netlist_load()` parses a Yosys JSON netlist and builds:
- `cells[]` — SB_LUT4 (16-bit truth table + 4 input nets + 1 output net), SB_DFF* (D/Q/clock/enable/reset/set nets), SB_CARRY (I0/I1/CI → CO)
- `hard_cells[]` — SB_SPRAM256KA (16K×16 SRAM), SB_RAM40_4K (256×16 block RAM)
- `ports[]` — top-level I/O with name, width, direction, net IDs per bit
- `eval_order[]` — topological sort of combinational cells (LUTs + carry + hard cell reads) for single-pass evaluation
- `dff_list[]` — indices of all DFF cells for clock-edge processing
- `clk_net` — auto-detected from port named "clk" or SB_HFOSC output

### Tick (one FPGA clock cycle)

```
1. eval_combinational(s)
   - Single pass through topo-sorted eval_order[]
   - LUT4: index = {I3,I2,I1,I0}, output = (lut_init >> index) & 1
   - CARRY: CO = (I0 & I1) | ((I0 ^ I1) & CI)
   - Hard cell reads: SPRAM/BRAM address → data lookup

2. eval_clock_edge(s)
   - Phase 1: Sample all DFF D inputs (pre-edge values)
   - Phase 1b: Hard cell writes (SPRAM/BRAM write using pre-edge address/data)
   - Phase 2: Update all DFF Q outputs simultaneously

3. eval_combinational(s) again
   - Propagates new DFF Q values through combinational logic

4. Pin change detection
   - For each output pin: read s->nets[pin->net_id]
   - If changed from previous level: fire gpio_set(&pin->out, new_level)
```

### Pin I/O

- `set_pin`: directly writes `s->nets[pin->net_id] = level`
- Output read: `s->nets[pin->net_id]` during change-detection scan
- The machine never touches `sim_state` directly

## Abstraction point

The seam is inside `ice40up5k.c`. Everything above (machines, callbacks) stays unchanged. Everything below (how simulation happens) gets swapped.

What stays in `ice40up5k.c` regardless of backend:
- Pin table (`struct ice40_pin pins[]`)
- Name lookup (`ice40up5k_find_pin`)
- Change detection loop (compare current vs previous level, fire callbacks)
- The `gpio_line` callback wiring

What gets swapped:
- How the design is loaded
- How a tick is executed
- How input pins are driven
- How output pin levels are read

## Backend implementations

### Backend 1: Built-in gate-level (current, `.json`)

- Input: Yosys `synth_ice40 -json` output
- Evaluates: LUT4 truth tables, DFF registers, carry chains, SPRAM/BRAM
- Speed: ~0.1x realtime for the PPU (729 cells × 2 combinational passes per tick)
- Value: matches post-synthesis netlist exactly, catches synthesis bugs (e.g., missing resets, clock domain issues, BRAM inference errors)

### Backend 2: CXXRTL (`.so`)

CXXRTL is a Yosys backend that compiles Verilog into a C++ class. Each signal becomes a struct member. No interpretation — compiled C++ executing direct assignments.

**Build pipeline:**

```bash
# Step 1: Yosys generates C++ simulation model
yosys -p "read_verilog fpga/*.v; synth_ice40 -top ppu_top; write_cxxrtl ppu_sim.cc"

# Step 2: Compile with the C wrapper into a shared library
g++ -shared -fPIC -O2 -o build/ppu_sim.so ppu_sim.cc cxxrtl_wrapper.cc \
    -I$(yosys-config --datdir)/include
```

**C wrapper (`cxxrtl_wrapper.cc`):**

```cpp
#include <backends/cxxrtl/cxxrtl.h>
#include "ppu_sim.cc"  // generated by yosys

static cxxrtl_design::p_ppu__top *top;

extern "C" {

void *fpga_create(void) {
    top = new cxxrtl_design::p_ppu__top;
    return top;
}

void fpga_destroy(void *ctx) {
    delete (cxxrtl_design::p_ppu__top *)ctx;
}

void fpga_tick(void *ctx) {
    auto *t = (cxxrtl_design::p_ppu__top *)ctx;
    // CXXRTL step() does: eval combinational, clock edge, eval combinational
    t->p_clk.set<bool>(false);
    t->step();
    t->p_clk.set<bool>(true);
    t->step();
}

void fpga_set(void *ctx, const char *name, int bit, uint8_t val) {
    // Map pin name to CXXRTL signal accessor
    // (generated code has p_SPI__CLK, p_SPI__MOSI, etc.)
}

uint8_t fpga_get(void *ctx, const char *name, int bit) {
    // Read output signal value
}

// Port enumeration for pin discovery
int fpga_num_ports(void *ctx);
const char *fpga_port_name(void *ctx, int idx);
int fpga_port_width(void *ctx, int idx);
int fpga_port_direction(void *ctx, int idx);  // 0=input, 1=output

}
```

**Runtime:** `ice40up5k_init` calls `dlopen("ppu_sim.so")`, resolves all `fpga_*` symbols, calls `fpga_create()`, then discovers pins by iterating `fpga_num_ports()`.

**Speed:** 50-100x faster than gate-level. PPU runs at ~5-10x realtime — game becomes playable in the simulator.

**Tradeoff:** Simulates RTL behavior, not post-synthesis. Won't catch synthesis-specific bugs (BRAM inference failures, clock domain crossing issues, etc.). Requires a recompile of the `.so` on every Verilog change.

### Backend 3: Verilator (`.so`)

Same concept as CXXRTL but using the Verilator tool instead of Yosys.

**Build pipeline:**

```bash
verilator --cc --top-module ppu_top -Mdir build/verilator fpga/*.v
make -C build/verilator -f Vppu_top.mk
# Wrap in .so with same C API as CXXRTL wrapper
g++ -shared -fPIC -O2 -o build/ppu_sim.so verilator_wrapper.cc \
    build/verilator/Vppu_top__ALL.a -I build/verilator
```

**Differences from CXXRTL:**
- Verilator is 2-state only (no X/Z) — same as the built-in sim
- Generally faster for large designs, similar for small ones
- Separate tool installation (not bundled with Yosys)
- Different signal access API (`top->SPI_CLK = 1` vs CXXRTL's `p_SPI__CLK.set<bool>(true)`)

**Same `.so` C API** — the wrapper just calls Verilator's API internally. From `ice40up5k.c`'s perspective, CXXRTL and Verilator `.so` files are interchangeable.

### Backend 4: Icarus Verilog (`.vvp`)

Icarus runs as a separate process. Communication via Unix pipe.

**Build pipeline:**

```bash
iverilog -o build/ppu_sim.vvp -s cosim_top fpga/*.v cosim_harness.v
```

**Co-simulation harness (`cosim_harness.v`):**

```verilog
module cosim_top;
    reg SPI_CLK, SPI_MOSI, SPI_CS;
    wire [7:0] LCD_D;
    wire LCD_WR, LCD_DC, LCD_CS;

    ppu_top uut (.*);

    initial begin
        // Read commands from stdin, write pin states to stdout
        // Protocol: binary, 1 byte cmd + payload
        forever begin
            // ... VPI or $fgets-based command loop ...
        end
    end
endmodule
```

**Runtime protocol (binary, over stdin/stdout pipe):**

```
Host → Icarus:
  0x01 pin_id value    — set input pin
  0x02                 — tick one cycle
  0x03                 — query all output pins
  0xFF                 — shutdown

Icarus → Host:
  After tick: num_outputs [pin_id value] × N
```

**Runtime:** `ice40up5k_init` forks `vvp build/ppu_sim.vvp`, opens pipes. `ice40up5k_tick` sends batched set-pin commands + tick command, reads back output pin states.

**Speed:** Slowest option (~0.01x realtime). IPC overhead + interpreted simulation.

**Value:** Full Verilog semantics including `$display`, `$dumpvars` for VCD waveforms, timing checks. Useful for debugging FPGA logic issues with GTKWave.

## Command-line interface

```bash
# Built-in gate-level (default):
./sim-core --machine gameboy-v2 --firmware game.elf \
    --device fpga0=build/ppu_top.json

# CXXRTL (fast, for interactive use):
./sim-core --machine gameboy-v2 --firmware game.elf \
    --device fpga0=build/ppu_sim.so

# Icarus (slow, for waveform debugging):
./sim-core --machine gameboy-v2 --firmware game.elf \
    --device fpga0=build/ppu_sim.vvp
```

Backend detected by file extension. No extra flags needed.

## Implementation changes

### `ice40up5k.h`

```c
struct ice40up5k {
    struct ice40_pin pins[ICE40_MAX_PINS];
    int num_pins;

    // Backend selection (exactly one is active)
    enum { FPGA_BACKEND_BUILTIN, FPGA_BACKEND_CXXRTL, FPGA_BACKEND_ICARUS } backend;

    // Built-in gate-level
    struct sim_state *fpga;

    // CXXRTL/Verilator (dlopen'd .so)
    struct {
        void *lib;          // dlopen handle
        void *ctx;          // fpga_create() return value
        void (*tick)(void *);
        void (*set)(void *, const char *, int, uint8_t);
        uint8_t (*get)(void *, const char *, int, uint8_t);
        void (*destroy)(void *);
    } dl;

    // Icarus (subprocess)
    struct {
        pid_t pid;
        int fd_to;          // pipe: host → icarus
        int fd_from;        // pipe: icarus → host
    } icarus;
};
```

### `ice40up5k_init` changes

```c
void ice40up5k_init(struct ice40up5k *dev, const char *path)
{
    memset(dev, 0, sizeof(*dev));
    int len = strlen(path);

    if (len > 5 && strcmp(path + len - 5, ".json") == 0) {
        dev->backend = FPGA_BACKEND_BUILTIN;
        // ... existing code (netlist_load, pin discovery from ports) ...

    } else if (len > 3 && strcmp(path + len - 3, ".so") == 0) {
        dev->backend = FPGA_BACKEND_CXXRTL;
        dev->dl.lib = dlopen(path, RTLD_NOW);
        dev->dl.ctx = ((void*(*)(void))dlsym(dev->dl.lib, "fpga_create"))();
        dev->dl.tick = dlsym(dev->dl.lib, "fpga_tick");
        dev->dl.set = dlsym(dev->dl.lib, "fpga_set");
        dev->dl.get = dlsym(dev->dl.lib, "fpga_get");
        dev->dl.destroy = dlsym(dev->dl.lib, "fpga_destroy");
        // Discover pins via fpga_num_ports/fpga_port_name/etc.

    } else if (len > 4 && strcmp(path + len - 4, ".vvp") == 0) {
        dev->backend = FPGA_BACKEND_ICARUS;
        // Fork vvp, set up pipes
    }
}
```

### `ice40up5k_tick` changes

```c
void ice40up5k_tick(struct ice40up5k *dev)
{
    switch (dev->backend) {
    case FPGA_BACKEND_BUILTIN:
        // ... existing eval_combinational/eval_clock_edge code ...
        break;

    case FPGA_BACKEND_CXXRTL:
        dev->dl.tick(dev->dl.ctx);
        break;

    case FPGA_BACKEND_ICARUS:
        // Send tick command over pipe, read back pin states
        break;
    }

    // Pin change detection — IDENTICAL for all backends
    for (int i = 0; i < dev->num_pins; i++) {
        struct ice40_pin *p = &dev->pins[i];
        if (p->direction != 1) continue;
        uint8_t new_level = fpga_read_output(dev, i);  // dispatches per backend
        if (new_level != p->level) {
            p->level = new_level;
            gpio_set(&p->out, new_level);
        }
    }
}
```

### `ice40up5k_set_pin` changes

```c
void ice40up5k_set_pin(struct ice40up5k *dev, int pin_idx, uint8_t level)
{
    if (pin_idx < 0 || pin_idx >= dev->num_pins) return;
    struct ice40_pin *p = &dev->pins[pin_idx];

    switch (dev->backend) {
    case FPGA_BACKEND_BUILTIN:
        if (p->net_id >= 0) dev->fpga->nets[p->net_id] = level;
        break;
    case FPGA_BACKEND_CXXRTL:
        dev->dl.set(dev->dl.ctx, p->name, 0, level);
        break;
    case FPGA_BACKEND_ICARUS:
        // Buffer the set, send on next tick
        break;
    }
}
```

### What stays completely unchanged

- All machine code (`gameboy_v2.c`, `fpga_test.c`)
- The `gpio_line` callback mechanism
- Clock ratio logic in machine tick functions
- All existing tests (they pass `.json`, use built-in backend)
- The `--device fpga0=...` argument parsing in `main.c`

## Performance expectations

| Backend | File | Speed (PPU) | Build time | Use case |
|---------|------|-------------|------------|----------|
| Built-in | `.json` | ~0.1x realtime | 2s (yosys) | Post-synthesis verification, CI |
| CXXRTL | `.so` | ~5-10x realtime | 5s (yosys + g++) | Day-to-day development, gameplay |
| Verilator | `.so` | ~5-10x realtime | 8s (verilator + make) | Same as CXXRTL |
| Icarus | `.vvp` | ~0.01x realtime | 1s (iverilog) | Waveform debugging with GTKWave |

## Implementation order

1. **CXXRTL backend** — highest value (makes game playable in sim)
   - Write `cxxrtl_wrapper.cc` template (~80 lines)
   - Add dlopen path to `ice40up5k_init` (~30 lines)
   - Add dispatch to `ice40up5k_tick` and `ice40up5k_set_pin` (~10 lines)
   - Add `make ppu_sim.so` target
   - Test: `./sim gameboy-v2` with `.so` shows same display output as `.json`

2. **Icarus backend** — useful for debugging
   - Write `cosim_harness.v` with VPI command loop
   - Add fork/pipe logic to `ice40up5k_init`
   - Add IPC protocol to tick/set_pin
   - Test: same display output, can generate VCD

3. **Verilator backend** — optional, same `.so` API as CXXRTL
   - Write `verilator_wrapper.cc`
   - Add Makefile target
   - No changes to `ice40up5k.c` (reuses CXXRTL dlopen path)

## Verification

For any backend swap to be trustworthy, the built-in gate-level sim remains the reference. Verification strategy:

1. Run the FPGA test suite (`test_fpga_ppu` etc.) with both `.json` and `.so` backends
2. Compare: both must produce identical pin-level behavior (same output transitions in same order)
3. The gate-level sim catches synthesis bugs that RTL sims miss — keep it in CI
4. Use CXXRTL for interactive development where speed matters

A simple regression test: capture a trace of all output pin transitions for a known input sequence using the `.json` backend, then replay the same inputs with the `.so` backend and diff the traces. Any difference indicates a simulation divergence.
