# gameboy-v4 — SoC Comparison

Research/planning, 2026-08-26. **Legend:** ✅ good · ⚠️ caveat/unverified · ❌ fails. *Games "build"
= a game you'd write; "emu" = consoles you could play. "Web" = browser snappiness. LCSC `~$` ⚠️ =
confirm on the live JLCPCB page before ordering. HDI = needs blind/buried/laser microvias (PCBWay-class
premium; JLC standard is through-hole only).*

**Two GPU columns:**
- **GPU (tier · model):** power tier `T5` (top) → `T1` (bottom); `T0` = no open driver — see ranking table.
- **Driver stack:** a GPU driver has two halves — a **Kernel** driver (manages the GPU in Linux) and a
  **Userspace** driver (Mesa; compiles shaders, *is* the GLES/Vulkan implementation). Each is marked
  **✅ open** / **❌ closed**. **API** = what that open driver delivers. **Firmware** = a separate sealed
  binary that runs *inside the GPU chip*. **A GPU is "open" when both Kernel + Userspace are ✅.**

**YouTube (HW decode):** YouTube serves **VP9** (most ≥1080p) and increasingly **AV1**; **H.264** is only
a ≤1080p fallback. So: **✅** = hardware VP9 (/AV1) decode *usable on mainline* → smooth · **⚠️** =
H.264/H.265 only on mainline (VP9/AV1 absent, dead in the mainline driver, or BSP-only) → works via the
`h264ify` browser extension but capped ~1080p · **❌** = no video decoder → software only, stutters.
*Key gotcha: mainline **Cedrus** (all Allwinner) supports **no VP9/AV1**, so Allwinner VP9 silicon is
unusable on a mainline kernel.*

## GPU power ranking (the tier tag used in the GPU column)

Higher tier = more powerful. Ranked by real-world capability **on the open driver** — hardware that's
stronger only via a closed blob is ranked by what the open driver actually delivers.

| Tier | GPU(s) — chip | Open API | What that tier actually runs |
|---|---|---|---|
| **T5** (top) | Mali-G610 MP4 — **RK3588** | GLES 3.1 + **conformant Vulkan**, ~512 GFLOPS | **Unreal** (UE4 well, UE5-mobile); Switch/PS2 emulation; desktop-class |
| **T4** | Mali-G52 MP4/MP6 — **Amlogic A311D/S922X** | GLES 3.1 (multi-core) | Strong 3D + UE4; GameCube/PS2 emulation |
| **T3** | Mali-T860 (**RK3399**) ≈ Mali-G57 (**A523/T527**) ≈ Mali-T760 (**RK3288**) ≈ Mali-G52 2EE (**RK3566/68**) | GLES 3.1 (no conformant Vulkan) | **Unity** + native **N64→GameCube/PS2-class** 3D; light UE4 |
| **T2** | Mali-G31 MP2 (**T507**, **H616/H700**) · GC7000UL-via-Etnaviv (**i.MX8M Plus**, open-limited) | GLES 3.1 entry / ~3.0 | Light Unity; **N64/PSX-class** 3D |
| **T1** | Mali-450 (**RK3328/S905**) > Mali-400 (**A64**) > T720-as-GLES2 (**H6**) > GC NanoUltra (**i.MX8M Mini**) > **GC Nano (STM32MP157)** ← weakest | **GLES 2.0 only** | **2D + pseudo-3D** (Mode-7 racer, Doom-style raycaster); no modern shaders |
| **T0** | PowerVR GE8300 — **A133** | **none** (no open driver) | Unusable on the open stack |

> Within **T3** the four are close (workload-dependent): 4-core Midgard T760/T860 have more raw
> throughput (~67 GFLOPS); single-core G52 2EE (~38 GFLOPS) and G57 are newer/more-efficient
> Bifrost/Valhall. Treat them as one "solid Unity / N64-GameCube-class" band.
